# Crowdin pilot

This is an experimental, reversible integration on the
`codex/crowdin-pilot` branch. It does not change the application runtime format
and it cannot open translation pull requests against `main`.

## What remains authoritative

- English messages, stable IDs, and descriptions remain in TypeScript/TSX.
- `src/locales/registry.ts` remains the locale and alias registry.
- `src/locales/lang/*.json` remains the reviewed application catalog format.
- `whitelist_<locale>.json` continues to identify values intentionally kept in
  English.
- `src/locales/lang.compiled` remains a generated production artifact.

Crowdin is only the hosted editing and review layer. Files under
`src/locales/crowdin` are ignored exchange artifacts generated by FormatJS.

## Pilot scope

The first project should contain only French (`fr`) and Turkish (`tr`). French
tests a nearly complete catalog; Turkish tests a partially complete one. Both
currently pass FormatJS structural validation. Regional language-code mapping
will be added only after the two-language round trip succeeds.

## Local commands

Generate the source catalog with all translator descriptions:

`pnpm run translations crowdin extract`

Generate filtered seed catalogs. Values that merely repeat English are omitted,
except for keys explicitly listed in that locale's whitelist:

`pnpm run translations crowdin seed fr tr`

After downloading translations with Crowdin CLI, validate and merge them into
the application catalogs:

`pnpm run translations crowdin import fr tr`

The import is deliberately an overlay during the pilot: missing downloaded
values do not erase an existing translation, unknown IDs fail, whitelisted
values stay English, and FormatJS verifies ICU structure before writing.

## Crowdin setup

1. Apply for and receive the free Crowdin Open Source license.
2. Create a public project with English as the source language.
3. Add only French and Turkish as target languages.
4. Create a personal token with project read access plus source-string and
   translation read/write access.
5. For local testing, export `CROWDIN_PROJECT_ID` and
   `CROWDIN_PERSONAL_TOKEN`; never add either value to `crowdin.yml`.
6. Generate the source and seeds, then use Crowdin CLI to upload them:
   `pnpm dlx @crowdin/cli upload sources` followed by
   `pnpm dlx @crowdin/cli upload translations`.
7. Download with `pnpm dlx @crowdin/cli download translations
--skip-untranslated-strings`, then run the import command and inspect the
   resulting locale diff.

## GitHub Actions trial

After adding `CROWDIN_PROJECT_ID` and `CROWDIN_PERSONAL_TOKEN` as repository
Actions secrets, the `Crowdin Pilot` workflow can perform the same round trip.
It is manually dispatched, checks out `codex/crowdin-pilot` explicitly, and
opens or updates `crowdin/pilot-translations` with a pull request whose base is
also `codex/crowdin-pilot`.

Set `upload_existing_translations` on the first run to seed Crowdin. Leave it
off on subsequent runs so Crowdin remains the editing source for the pilot.

GitHub only exposes manually dispatched workflows after the workflow exists on
the default branch. Until this pilot is accepted, run the equivalent Crowdin
CLI commands locally on `codex/crowdin-pilot`; do not merge the workflow merely
to make the button appear.

## Acceptance checks

- Crowdin displays source descriptions and ICU variables correctly.
- English placeholders are not counted as translated.
- Intentionally English whitelist entries survive the round trip.
- Downloaded updates change only `fr.json` and `tr.json`.
- The pull request passes the complete test and build pipeline.
- Removing the pilot requires deleting only the Crowdin project/configuration,
  the ignored exchange directory, the workflow, and the Crowdin command module.
